# 多 Agent 科普视频生成需求

## 目标

FrameCraft 根据主题、文案或音视频生成高质量科普解说视频。每个任务由同一个多 Agent 团队从内容理解、动画设计、代码实现、整合渲染到视觉验收全程负责，禁止用固定模板换文字冒充 Agent 设计。

## 必须实现

1. 内容 Agent 生成或整理逐字稿、事实边界、分镜和来源；文案及媒体模式必须严格保持用户原意。
2. 总导演 Agent 制定本片独有的色彩、构图、运动语言和场景衔接，避免复用其他视频的视觉结构。
3. 每幕由独立动画 Agent 直接生成可运行的 SVG、HTML、CSS 和 GSAP 代码。输出必须包含独特角色、空间结构、入场、持续运动、状态演化和退场。
4. 动画 Agent 可以调用通用底层能力，如时间轴、字幕、音频和安全区；不得选择整幕成品模板，也不得只输出母题名称、参数或设计说明。
5. 代码审查 Agent 检查语法、性能、时间边界、文字安全和元素重叠。整合 Agent 仅统一全片时间轴、主题变量、转场和音频，不得把逐幕代码替换成模板。
6. HyperFrames 必须使用严格模式真实渲染。不得使用 FFmpeg 拼接画面、复制旧成片或静态截图兜底。
7. 视觉验收 Agent 必须查看每幕入场、中段、退场截图，并与历史成片进行结构相似度检查。发现构图单调、旧视觉换皮、PPT 感、遮挡、空白失衡、文字不可读或动画缺乏语义时，标记对应页面待重画并在对话中展示评分与问题，不得自动启动重画。
8. 用户明确说“重试”或点击“重试”按钮后，提示词 AI 读取该幕三帧和完整验收问题，形成新的逐页设计提示词，再交给动画 AI。未被点名的场景仍需保持风格连续，避免无关随机改动。
9. 初版生成完成后才启动可执行对话。初版前用户聊天只提示先完成初版，不启动修改任务。
10. 对话 AI 专门负责读当前项目工程代码、应用需求、聊天历史和用户意图，并判断 `answer`、`regenerate` 或 `fine_tune`。重新生成必须经用户按钮确认后交给提示词 AI 完整重跑；微调必须经用户按钮确认后由对话 AI 修改现有 HyperFrames 工程文件，再重新本地渲染和验收。
11. 校验不通过且已有可播放成片时不得自动重试。唯一例外是根本没有生成可播放 MP4，这时可以自动修复工程并重试，最多 3 次，之后必须回到聊天说明问题。

## 画面规范

- 字幕使用简体中文，固定在底部居中安全区，并有渐入渐出。
- 来源短注固定在画布左下角，与字幕保持间距。
- 观众画面不得出现提示词、制作步骤、场景编号、调试信息等幕后文案。
- 每幕动画结构应服务当前内容；流程逐节点展开，数据与结论可追溯，不虚构数字。
- 主视觉充分利用画幅，元素不互相遮挡；底板按需使用半透明效果，方框采用真实圆角。

## 通过标准

交付物必须保存完整 Agent 轨迹、每幕源代码、整合工程、HyperFrames 渲染日志和视觉验收记录。只有代码确由逐幕 Agent 生成、成片完整、音画同步、主观审美通过且无历史模板换皮，任务才可登记成功；任何环节失败都应在项目聊天中如实说明。已有可播放失败成片时等待用户决定，无法播放时按上限自动修复。
