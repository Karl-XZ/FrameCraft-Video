# 一键科普视频生成工作流

本文档是项目 Agent 的执行规范。实现参考 `ai-science-video-maker` 中的叙事、视觉、来源与本地制作原则，并按 FrameCraft 的 DeepSeek、阿里云语音、HyperFrames 和用户本地渲染架构重新实现。

## 1. 三种输入模式

### 主题模式

用户提供主题、受众和额外要求。DeepSeek 生成科普讲稿、章节、每章视觉主张、语义动画类型和来源候选。只有可公开访问的 HTTPS 来源进入 `SOURCE_LEDGER.md`。通过验证仅代表链接可访问，内容 Agent 仍需检查来源与表述是否对应。

### 文案模式

用户文案是唯一内容原文。系统可以按标点拆成 TTS 和分镜片段，不得改写、概括、补充或重新排序。阿里云 TTS 生成旁白；字幕必须完整覆盖原文。

### 媒体模式

用户上传音频或视频。视频只提取原音轨，阿里云 ASR 生成逐字稿。最终成片必须使用原音频，不能用 TTS 重配。ASR 文本只服务于字幕和视觉设计。

## 2. 内容与来源

1. 一章只解释一个核心概念，并给出一句可视化主张。
2. 精确数字、研究结论和机构口径必须关联来源编号。
3. 无法可靠核对的数据改用定性表达，不生成看似准确的虚构刻度。
4. 来源短注固定在画布左下角安全位，横竖版都不得随主视觉布局移动；字幕仍固定在底部居中，两者必须保留垂直间隔。
5. 观众画面禁止出现“场景、制作、动画、工作流、Agent、FrameCraft”等幕后词汇。
6. 文案尽量避免使用“不是……而是……”句式。

## 3. 语义动画分类

每场选择一个主导语义运动，不能只更换标题后复用同一块面板。

| 类型 | 适合内容 | 主动画 |
| --- | --- | --- |
| `mechanism` | 因果、传播、形成过程 | 粒子或信号沿路径依次穿过节点 |
| `scale` | 大小、距离、强弱、范围 | 同心尺度场、层级缩放和相对距离 |
| `comparison` | 两类对象或条件差异 | 双侧对照、共同基准和差异显现 |
| `timeline` | 演化、周期、历史过程 | 曲线或轨道上的节点逐个推进 |
| `system` | 组成、关系、生态或网络 | 中心概念与外围节点动态连接 |

每个关键元素都要有入场、持续运动和退场。流程节点必须逐个出现。持续运动应表达含义，例如粒子传播、轨道运转、尺度呼吸或状态迁移，不能只做无目的漂浮。

## 4. 画面规则

- 字幕使用简体中文，固定居中放在底部安全区，并有短促渐入渐出。
- 主视觉应占据足够面积，避免大片无意义空白，也不能压住字幕和来源。
- 圆角必须由真实 `border-radius` 实现；底板优先半透明，不默认给每个元素加实色方框。
- 相邻分镜改变空间结构、视觉焦点或运动方向，不能形成连续 PPT 页面。
- 一秒内应能辨认本场科学焦点；屏幕文字只承担标题、短标签和关键关系，完整解释交给旁白。
- 16:9 与 9:16 分别布局，不能把横版机械缩放成竖版。

## 5. Agent 与工程产物

每个项目拥有独立 Agent 上下文、素材目录、聊天记录和版本目录。一次任务中的所有 Agent 由同一个 openJiuwen TeamRuntime 管理，并共享当前项目输入，不读取其他项目内容。

标准协作顺序：

1. 内容、视觉和时序专家并行给出事实边界、科学隐喻与可读性建议。
2. 总导演综合专家意见，建立本片独有的色彩、字体、运动语言和连续性装置，并为各幕分配不同视觉母题。
3. 每幕启动一个独立设计与编码 Agent，直接输出当前幕的 SVG/HTML、作用域 CSS 和 GSAP 时间线源码。设计说明不能代替源码。
4. 每幕由独立代码审查 Agent 检查语义、可执行性、安全边界、主视觉面积、持续运动和退场；不合格时退回原设计 Agent 完整重写。
5. 整合导演只统一文字层级、主题变量和场景衔接。程序必须原样保留通过审查的逐幕源码，禁止用固定模板重新编译。
6. 方案审片 Agent 检查科学对应关系、场景差异、角色数量和动画节拍；低于 85 分不得进入渲染。
7. 通用编译器仅提供音频、字幕、画布、安全区和时间轴运行环境。旧科学母题模板不参与当前生成链路。

每幕必须使用唯一代码命名空间，且与其他场景具有不同的 DOM、SVG 路径和时间线结构。`premium-stage`、`pm-*`、`science-board` 等旧模板标记会触发硬失败。

必须产出：

- `analysis/analysis.json`
- `analysis/edit_plan.json`
- `analysis/creative_plan.json`
- `analysis/agent_trace.json`
- `input/scene_seed.json`
- `input/transcribe/transcript.json`
- `input/SOURCE_LEDGER.md`（主题模式）
- `<version>/timeline.json`
- `<version>/subtitles.srt`
- `<version>/scene-sources/`（逐幕 HTML、CSS、GSAP 与生成审查清单）
- `<version>/hyperframes/`
- `<version>/hyperframes_project.zip`
- `<version>/agent_visual_review.json`

## 6. 渲染与验收

1. 服务端 Agent 生成可复渲染工程包，不保存 MP4。
2. 网页在当前浏览器内挂载 HyperFrames 官方 runtime，并通过 `renderSeek` 确定性逐帧运行工程。
3. 浏览器使用 WebCodecs 编码 H.264/AAC MP4，并核对音视频轨、分辨率和完整时长。
4. 浏览器对每幕约 18%、50%、82% 三个时点采样，形成按幕排列的临时联系表；场景过多时均匀选择六幕，最多检查十八帧。
5. 视觉 Agent 对照真实分镜起止时间检查构图、语义、文字、字幕、来源与场景差异，同时比较三帧是否存在入场、持续演化和退场衔接。
6. 同一分镜的三张连续截图用于判断运动，不得误判为三个重复分镜。
7. 评分低于 82 或存在硬伤时保留失败成片，不登记为通过版本，也不自动重试。中间页面继续提供本机成片播放，Agent 对话显示验收分数、问题清单与“重试”按钮。
8. 只有用户在对话中明确说“重试”，或点击“重试”按钮后，系统才把完整验收意见反馈给提示词 AI，由提示词 AI 重写问题页面的设计提示词，再交给动画 AI 生成新工程并重新真实渲染。
9. 如果浏览器根本没有生成可播放 MP4，例如工程无法启动、编码没有返回视频或媒体探测缺少必要轨道，系统可自动把错误反馈给提示词 AI 修复工程，最多连续 3 次；超过上限后转入聊天说明，由用户决定下一步。
10. 联系表验收后删除，MP4 只存在于当前浏览器并由用户自行下载；用户无需安装本地服务或辅助程序。

## 7. 初版后的对话改片

Agent 对话只在初版完成后进入可执行状态。初版完成前用户发送消息时，系统只提示“请先完成初版生成”，不启动生成任务，也不伪装已经进入改片。

初版完成后，每条用户消息先交给对话 AI。对话 AI 必须读取当前项目需求、聊天记录、最新版本 timeline、验收记录和 HyperFrames 工程代码摘要，然后给出三类判断：

- `answer`：只回答用户问题，不显示操作按钮。
- `regenerate`：用户想改主题、重写结构、整体换风格或大幅提高质量时，显示“重新生成”按钮。用户点击后，对话 AI 把整理后的需求交给提示词 AI，提示词 AI 重新规划全片。
- `fine_tune`：用户只想改字幕、局部元素、少量页面、速度、色彩或来源标注时，显示“微调”按钮。用户点击后，对话 AI 复制当前 HyperFrames 工程，只修改必要文件，再注册为新的本地渲染工程。

对话 AI 不能在未获用户按钮确认时直接改工程。重新生成和微调都必须重新经过浏览器本地 HyperFrames 渲染、媒体检查和视觉验收。

项目不提供 FFmpeg 静态合成、复制旧成片或伪造 Agent 成功的兜底路径。
